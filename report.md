# Звіт з контейнеризації ML-моделі

## 1. Порівняння образів

| Характеристика | Fat Image (ml-fat) | Slim Image (ml-slim) |
| :--- | :--- | :--- |
| **Base Image** | `python:3.9` (Debian based) | `python:3.9-slim` (Debian Slim) |
| **Розмір** | ~1.5 GB - 2.5 GB (залежно від версії torch) | ~200 MB - 350 MB |
| **PyTorch** | Standard (включає CUDA binaries) | CPU-only версія |
| **Метод збірки** | Single-stage | Multi-stage (Builder -> Runtime) |
| **Користувач** | Root | Non-root (appuser) |

## 2. Аналіз

### Проблеми Fat-образу:
1.  **Величезний розмір:** Стандартний `pip install torch` встановлює підтримку CUDA, яка займає сотні мегабайтів. Для inference на CPU це мертвий вантаж.
2.  **Безпека:** Запуск від імені `root` за замовчуванням є поганою практикою.
3.  **Кеш:** `pip` зберігає кеш пакетів всередині образу, збільшуючи його розмір без користі для роботи.
4.  **Системне сміття:** Базовий образ містить багато непотрібних утиліт Linux.

### Переваги Slim-образу:
1.  **Multi-stage:** Ми компілюємо/встановлюємо залежності на першому етапі, а в фінальний образ копіюємо лише папку `venv`.
2.  **CPU-only Torch:** Використання `--index-url https://download.pytorch.org/whl/cpu` — це головний фактор зменшення розміру (економія ~700MB+).
3.  **Безпека:** Створено окремого користувача `appuser`.
4.  **Чистота:** Фінальний образ не містить компіляторів (`build-essential`) та кешу `pip`.

## 3. Пропозиції з подальшої оптимізації
1.  **Distroless Images:** Використати `gcr.io/distroless/python3-debian11`. Це прибере навіть оболонку shell, зробивши образ максимально легким і безпечним.
2.  **ONNX Runtime:** Конвертувати `.pt` модель в ONNX. ONNX Runtime значно легший та часто швидший за повний PyTorch.
3.  **Quantization:** Використати квантування (int8) для зменшення розміру самої моделі та прискорення роботи.
